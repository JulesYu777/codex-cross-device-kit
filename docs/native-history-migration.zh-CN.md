# Windows → Mac 原生聊天迁移设计

[English](native-history-migration.md) · [简体中文](native-history-migration.zh-CN.md)

本文定义工具包拟实现的一次性迁移环节。用户从 Windows 选择并导出旧聊天，在 Mac 上配置项目映射。工具自动复制历史、适配运行路径，并从 Mac 本机 Codex 验证。项目文件沿用工具包现有的 Syncthing 流程，批量迁移需要显式选择。

## 用户流程

| 步骤 | 拟提供的命令 | 结果 |
| --- | --- | --- |
| Windows 导出 | `py -3 kit.py history export --select selection.json --out BUNDLE` | 生成所选聊天和必要历史分段的本地迁移包 |
| Mac 预检 | `python3 kit.py history plan BUNDLE --map workspace-map.json --out PLAN` | 生成计划，报告可导入、已存在、可修复和需跳过的聊天 |
| Mac 应用 | `python3 kit.py history apply PLAN` | 备份 Mac 本机数据，应用通过预检的条目，并以原生 Codex 读回核验 |

Mac 项目先通过已核对的 Git 仓库或本机目录准备就绪。用户通过私人渠道传递迁移包，Mac 桌面空闲时，应用步骤负责正常退出并重开。若有会话正在运行，则等待或报告需先结束的会话。重开后，在 Mac Codex 的「本机」视图打开原聊天。

## 导出、映射与隔离预检

- **Windows 源。** 选择器接受原生本机聊天 ID。使用源 Codex 读取选中聊天、完整分页轮次、可用项目归属及归档状态。复制所选原生历史文件及完整的分段依赖。清单记录格式版本、源构建版本、原聊天 ID、项目根路径、相对归档路径、字节数与 SHA-256，并记录每条聊天的源轮次与内容指纹。对活跃聊天或导出期间发生变化的源记录，等待其稳定后重新导出。
- **迁移包。** 限定文件清单、文件类型和解包大小。验证清单与内容哈希，拒绝越界路径、重复路径和符号链接。导出范围只包括选中历史和必要元数据，账号缓存、认证文件、配置和项目素材留在各自主机。聊天正文可能含敏感信息，迁移包应按原始聊天的私密级别保存和传输。
- **Mac 映射。** 将 Windows 项目根目录映射到实际存在的 Mac 绝对路径，Git 项目可用规范化后的远端地址确认归属。同名项目按根目录和 Git 远端验证。按路径组件匹配最长已登记前缀。运行目录使用确认过的 Mac 项目根目录，额外工作区根只接受已映射并存在的 Mac 目录。没有额外目录时写入空数组。主项目无法唯一定位的条目跳过并请求补全映射。
- **原生记录。** 只改面向目标主机的会话恢复元数据，保持原聊天 ID。保留消息、工具记录和其内部的历史证据路径。保持依赖分段及受引用的字节偏移。对于已验证的分段格式，可原长替换当前段首行，空格填充至原长度。首行无法原长写入或分段链接无法校验时，跳过该条目。
- **隔离读回。** 以 Mac 实际安装的 App Server 在独立且断网的副本中恢复。实际分页核对原 ID、轮次顺序、轮次状态和稳定内容指纹，验证本机工作目录以及目标项目归属。盘点和补齐全部分段后才进入这一步。通过版本组合与格式覆盖的条目才可应用。不同或不支持的构建需先跑兼容性测试。 [Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)

## 写入与恢复

- **同 ID 处理。** Mac 本地无同 ID 时导入。若历史指纹相同且已可打开，视为已迁入。若指纹相同且仅工作区恢复失败，自动修复 Mac 现有记录。若指纹不同或 Mac 验证不完整，保留双方记录并跳过。重新预检时，将已成功应用的条目归为已存在。
- **项目归属。** 优先使用已核验的本机项目 ID 或工作目录归属。仅在已验证构建的原生项目接口允许时创建新项目或登记归属，并在项目列表中读回核验。已有项目无法验证归属时跳过该条；归档状态按已验证接口恢复。分区、置顶和原生附件各自通过兼容性验收后再开放。
- **备份与应用。** 对计划绑定源清单哈希、映射哈希、Codex 构建及 Mac 目标基线。应用前重新检查，变化时重新预检。确认 Mac 相关进程已停止且记录未变化，备份受影响的 Mac 聊天文件和索引，校验备份。通过以 Mac 工作目录启动的已验证本机 App Server 建立原生索引。记录每次文件落盘和索引恢复操作。应用过程发生错误时，在桌面重开前按备份回滚本批；桌面重开后检测到新 Mac 写入时，保留新增内容并停止自动覆盖。
- **最终验收。** Mac 本机聊天列表能按原 ID 找到并打开聊天，在目标项目下显示，最新及最早轮次都可见，且原有 Mac 聊天和 Windows 来源保留。收据按条记录导入、修复、已存在、跳过或已回滚，并给出原因和备份位置。回执省略聊天正文和凭据。

## 发布验收

1. 用公开合成样本从 Windows 导出，在 Mac 空目标及已有新聊天的目标分别导入。原生列表、原 ID、轮次和项目归属均应一致。
2. 覆盖 Windows 盘符、中文与空格路径、不同 Git 本机目录、多个根、空额外根、重复导入和同 ID 不同内容。模拟分段缺失、偏移损坏、版本不兼容、运行中文件变化和中途失败，验收跳过和回滚。
3. 用已获授权的真实跨版本样本，在 Mac 桌面关闭并重开后验收原聊天仍能打开。单独用合成聊天验证后续新轮可继续追加。只有经该流程通过的版本组合进入公开支持列表。

现有证据验证了分段文件齐全时的工作区路径修复。同一条真实聊天在隔离环境中恢复了 59 个内容与顺序一致的轮次，随后在 Mac 桌面原生打开。此前也观察过仅部分回放或分段投影不一致，因此这类记录应被预检拦截。迁移命令、打包和回滚仍是本设计的实现项。
